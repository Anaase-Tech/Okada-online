OKADA ONLINE — PRODUCTION SETUP (V4 STABILIZED)

Repository
  Anaase-Tech/Okada-online
  Branch: v4-mobility-os
  Firebase project: okada-online-ghana

ACTIVE AUTHENTICATION
  Firebase Phone Authentication is the production phone-auth path.
  The web app uses Firebase client-side phone verification.
  The backend verifies Firebase ID tokens.
  Twilio is NOT used by the active Cloud Functions package.

PAYMENTS
  Paystack is the active payment provider.
  Secrets remain server-side.
  The current backend reads the Paystack secret through functions.config().
  Firebase documents functions.config() as deprecated and states that new
  deployments using it will fail after March 2027. Migrate the Paystack secret
  to parameterized configuration / Secret Manager before that deadline.
  Source: https://firebase.google.com/docs/functions/config-env

JOURNEY PAYMENT LIFECYCLE
  Journey created:
    PENDING_PAYMENT + paymentStatus=PENDING
  Payment initialized:
    PENDING_PAYMENT + paymentStatus=PAYMENT_PENDING
  Provider-verified success:
    CONFIRMED + paymentStatus=PAID
    transit bookings move PAYMENT_PENDING -> CONFIRMED
  Provider failure:
    CANCELLED + paymentStatus=FAILED
    held inventory released
  Payment expiry:
    CANCELLED + paymentStatus=EXPIRED
    held inventory released
  Late provider success after release:
    paymentStatus=PAID + refundStatus=REQUIRES_REVIEW
    no automatic false refund/fulfilment is claimed

  The webhook validates the Paystack signature and delegates settlement to the
  transactional Journey payment service. The frontend cannot mark a payment
  successful.

PAYSTACK CALLBACK / RECOVERY
  Journey payment initialization returns Paystack authorization_url.
  The Journey screen keeps the Journey ID and payment reference locally.
  After return it attempts server-side Paystack verification once; the webhook
  remains the asynchronous source of truth.
  Paystack references generated by Okada use only Paystack-supported characters.

BACKEND DEPLOYMENT
  cd backend
  npm install
  firebase login
  firebase use okada-online-ghana
  firebase deploy --only functions

  The Functions source is backend/functions and its package.json declares:
    main: v4Entry.js
    node: 20

  v4Entry.js captures the existing legacy Express app, keeps the legacy terminal
  404 ordering intact, then mounts the V4 routers. This is an extension layer;
  it does not replace the legacy app.

  V4 mounts:
    /trotro       -> trotroRoutesV2.js
    /trotro-admin -> trotroAdminRoutes.js
    /transit      -> transitRoutes.js
                    transitBookingRoutes.js
                    transitHubRoutes.js
                    vipTransitRoutes.js
    /journeys     -> journeyBookingRoutes.js

FIRESTORE
  backend/firestore.rules denies direct client writes to sensitive application
  collections; V4 journey/transit collections rely on backend APIs.
  backend/firestore.indexes.json includes the V4 composite indexes used by
  segment inventory, journey events, transit searches, and Journey expiry.

FRONTEND
  web-app is a Create React App project.
  Build:
    cd web-app
    npm install --legacy-peer-deps
    npm run build

  Vercel configuration is in web-app/vercel.json.
  REACT_APP_API_URL can override the API endpoint; the current default is:
    https://us-central1-okada-online-ghana.cloudfunctions.net/api

IMPORTANT CURRENT LIMITATIONS
  1. This audit environment can inspect the live GitHub branch but cannot run
     npm against the repository checkout because the checkout/node_modules are
     not available here and outbound package installation is unavailable.
  2. A Node-compatible audit harness executed the current pure V4 tests:
     26 functional test cases, 0 failures.
  3. A complete production Firebase/Paystack transaction was not executed in
     this audit. Paystack credentials and webhook registration must be verified
     in the Firebase/Paystack consoles before launch.
  4. Full CRA production build was not executed here.
  5. Firestore transaction serialization was inspected and protected by shared
     trip-document writes, but a live contention test against the Firestore
     emulator was not executed here.
  6. The active legacy rate limiter is in-memory/instance-local, not a global
     distributed rate limiter.
  7. Pickup/final-mile paid pricing is intentionally blocked unless a trusted
     backend quote exists; the system does not accept arbitrary client fares.
  8. functions.config() should be migrated before the March 2027 decommission
     deadline.

TROTRO MODULE AUTHORITY
  trotroRoutesV2.js is the mounted production router.
  trotroRoutes.js is retained as an unmounted alternate/legacy implementation.
  It was not deleted because the stabilization rule is to preserve existing
  source and avoid destructive cleanup without migration evidence.
