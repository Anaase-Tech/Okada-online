OKADA ONLINE — QUICK START (V4)

1. Clone/open Anaase-Tech/Okada-online and use branch:
   v4-mobility-os

2. Web application:
   cd web-app
   npm install --legacy-peer-deps
   npm run build

3. Firebase backend:
   cd backend
   npm install
   firebase login
   firebase use okada-online-ghana
   firebase deploy --only functions

4. Authentication:
   Firebase Phone Authentication is used by the production web app.
   Do not configure Twilio for the active Functions package.

5. Paystack:
   Configure the server-side Paystack secret for the Firebase Functions
   environment and configure the Paystack webhook to point to the deployed
   /payments/webhook endpoint.

6. Journey:
   Search transit -> select segment(s) -> Book Journey -> Paystack -> provider
   verification/webhook -> Journey becomes PAID/CONFIRMED -> Journey Pass.

7. Operations:
   Admin users use the Transit Operations console to record real operational
   events. The Journey state is derived from recorded events and stored trip
   state; the system does not invent GPS or ETA.

8. Trotro:
   /trotro uses trotroRoutesV2.js. Segment inventory is calculated per route
   segment, and booking transactions touch the shared trip document to force
   concurrent transaction retries instead of overselling.

9. Safety:
   Keep Paystack secrets server-side. Do not mark payment successful from the
   client. Do not submit another user's userId/driverId to act on their behalf.

10. Current deployment source:
    backend/firebase.json -> functions source "functions"
    backend/functions/package.json -> main "v4Entry.js", Node 20

Note:
Firebase currently documents functions.config() as deprecated and says new
deployments using it will fail after March 2027. Migrate before that deadline.
